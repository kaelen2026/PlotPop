# AI 漫剧 SaaS 产品设计规格

## 1. 产品概述

本产品是一款面向全球市场、英文优先的 AI 漫剧创作 SaaS。产品首发北美，帮助创作者通过“单集脚本 + 可复用角色设定”生成一集 5–10 分钟的完整漫剧视频。

MVP 首先服务个人漫剧创作者，同时在产品结构上为未来的小型制作团队预留扩展空间。商业模式采用一次性积分包，不提供订阅套餐。

## 2. 产品目标

- 让新用户通过脚本和角色设定，生成一集完整的 5–10 分钟漫剧。
- 通过向导式自动创作降低首次使用门槛。
- 为专业创作者提供逐镜头控制，避免修改局部内容时重新生成整集。
- 在同一系列的不同剧集中维持角色与视觉风格一致性。
- 清晰展示生成成本，并可靠处理长时间任务与生成失败。
- 打通官网获客、注册、购买积分、创作、审阅和导出的完整闭环。

## 3. 目标市场与产品定位

- 首发市场：北美。
- 产品准备：从第一版开始支持全球化扩展。
- 首版界面语言：英文。
- 核心用户：制作连载漫剧的个人创作者。
- 核心产物：可发布的 5–10 分钟完整单集。
- 品牌定位：充满活力、对创作者友好、适合社交内容生态的 AI 制作工作室。

所有用户界面文案必须从可本地化资源中读取，不得将文案硬编码在组件内。

## 4. 视觉方向

已批准的视觉方向为 **Pop Anime（流行动漫风）**：

- 明亮且易识别的大色块。
- 漫画式深色描边和紧凑投影。
- 富有活力的字体与趣味几何造型。
- 在鲜明的视觉表达之下，保持清晰的制作流程层级。
- 体现创作者工具气质，避免传统企业后台风格。

建议基础色板包含暖白背景、墨黑描边、亮粉、天蓝、酸性绿与暖黄。颜色不能作为状态的唯一表达方式，必须结合文字和图标，满足无障碍要求。

## 5. 产品信息架构

### 5.1 公开访问区域

- 官网首页：作品案例、产品原理和主要注册入口。
- Explore 案例页：展示精选剧集与使用场景。
- Credits 积分页：展示一次性积分包与易理解的用量估算。
- 注册、登录和账户恢复。

### 5.2 创作者首页

- Series 系列管理，以及可复用的角色与风格资产库。
- 项目和剧集列表，按草稿、生成中、待审阅、已完成和失败分类。
- 积分余额、购买入口和消费记录。
- 新建剧集入口。

### 5.3 双层创作系统

产品包含两个相互配合的创作层：

1. 五步快速创作向导：**脚本 → 角色 → 分镜 → 动画 → 导出**。
2. 用于精细编辑场景和镜头的高级单集工作台 Episode Studio。

向导中的每一步都会产生可编辑草稿。用户在生成草稿后即可进入高级工作台，不必先走完整个向导。

## 6. 核心数据边界

### 6.1 Series（系列）

系列负责保存跨剧集复用的创作身份：

- 系列名称和元数据。
- 角色设定与参考图。
- 角色声音配置。
- 视觉风格手册。
- 默认画幅、字幕、节奏、音乐和运动偏好。

### 6.2 Episode（剧集）

剧集负责保存单次发布特有的内容：

- 原始脚本与脚本版本。
- 场景规划。
- 镜头列表与镜头版本。
- 台词、提示词和生成参数。
- 已生成的图片、视频、配音、音乐和字幕。
- 最终合成文件与导出记录。

剧集可以引用系列级资产，但剧集内的修改不得自动覆盖系列资产。用户必须主动选择，才能将剧集内的角色或风格变更同步到系列。

## 7. 核心创作流程

### 7.1 脚本

用户粘贴或上传英文脚本。系统提取角色、地点、台词、动作和场景边界。进入下一步之前，创作者可以检查并修改解析结果。

### 7.2 角色

系统将脚本中的角色匹配到已有系列角色，或建议创建新角色。用户检查角色名称、参考图、外观描述和声音。

### 7.3 分镜

系统生成场景与镜头草稿，内容包括时长、景别、台词、动作和提示词。进入高成本的视频生成之前，用户可以重排、新增、删除、拆分或合并场景与镜头。

### 7.4 动画

系统预估积分消耗并请求确认，随后预留预计积分，按镜头生成视频和音频任务。

- 自动模式应用项目默认配置。
- 高级模式开放镜头级运动、机位、台词、声音、时长和提示词控制。

### 7.5 导出

用户检查警告和失败镜头，触发最终合成，并可导出：

- 1080p MP4。
- 16:9 或 9:16 画幅。
- 内嵌字幕版本。
- 无内嵌字幕的纯净版本。
- 独立字幕文件。

## 8. Episode Studio 单集工作台

高级工作台包含三个主要区域：

- **场景导航区：**展示场景、镜头数量、时长、任务状态和新增、排序操作。
- **预览与时间线：**播放当前镜头，展示剧集上下文、镜头顺序和台词、音频时间。
- **镜头检查器：**编辑角色、提示词、台词、声音、机位、运动、时长、模型选项，并执行局部重生成。

顶部栏展示系列名称、剧集名称、当前积分余额、保存或同步状态、生成状态和导出入口。

所有生成资产均按镜头保存版本。重生成镜头会创建新的候选版本，并保留旧版本，直到用户主动删除。切换镜头候选版本只会使最终合成失效，不会影响无关镜头资产。

## 9. 生成数据流

生成管线为：

**脚本 → 场景规划 → 镜头提示词 → 视频与配音资产 → 单集合成**

每个阶段都保存可检查、可编辑的结构化结果。条件允许时，每个镜头的视频和音频任务独立运行。最终合成使用创作者批准的镜头版本和音轨。

自动模式：

- 自动使用预设节奏、声音、运动、音乐和字幕规则。
- 在执行高成本视频生成前停下，请求用户明确确认。

高级模式：

- 允许创作者调整单个场景和镜头。
- 在每个生成或重生成操作旁展示积分预估。

## 10. 积分与计费

- MVP 只销售一次性积分包。
- 积分包展示大致可生成的视频分钟数，并说明实际消耗受模型、分辨率、时长和重试次数影响。
- 脚本分析与低清分镜预览属于低成本操作。
- 视频生成、高清重生成和最终合成是主要积分消耗项。
- 执行付费生成操作前，界面必须展示预估并请求确认。
- 系统先预留预计积分，任务完成后再按实际消耗结算。
- 平台或模型服务商失败时，自动释放未使用的预留积分。
- 用户主动取消时，只收取已经完成的可计费工作。
- 消费明细中的每一笔扣除或释放，都必须关联到剧集、场景、镜头、操作类型和任务编号。

客户端不得计算权威余额。积分预留与结算必须在服务端以事务和幂等方式执行。

## 11. 长任务与恢复机制

整集生成需要拆分成可独立重试的场景或镜头任务。在服务商和账户限额允许的范围内，任务可以并行执行。

统一任务状态如下：

- Draft：草稿
- Queued：排队中
- Generating：生成中
- Needs review：待审阅
- Completed：已完成
- Failed：失败

服务端是任务状态的唯一可信来源。客户端订阅进度更新，并在订阅不可用时退回轮询。关闭页面、刷新页面或换设备登录，都不会中断服务端任务。

单个镜头失败不能阻塞其他镜头。最终合成前，系统集中展示所有未解决失败和可操作警告，包括：

- 角色一致性风险。
- 内容审核或政策拒绝。
- 音频缺失或生成失败。
- 不支持的素材格式。
- 新任务开始前积分不足。

重试操作必须具备幂等性。队列重复投递或服务商重复回调不得造成资产或扣费重复。

## 12. 隐私、安全与内容处理

- 项目默认私有。
- 发布到公开案例区必须由创作者主动操作。
- 上传流程要求创作者确认拥有素材使用权。
- 提示词和上传素材必须经过适当的内容安全检查。
- 内容被拒绝时，界面应说明原因类别；政策允许时，提供修改输入的路径。
- 用户可以删除项目和生成历史。
- 删除界面必须说明备份和服务商处理产物的保留周期。
- 敏感凭据和模型服务商密钥只能保存在服务端。

## 13. 异常体验

错误信息必须说明受影响的具体对象，保留已完成工作，并提供下一步操作。

- 表单内错误用于处理无效脚本、缺失角色参考和不支持的上传文件。
- 镜头卡片可以显示失败或警告状态，但不阻断用户浏览其他内容。
- 生成失败时，提供重试、修改输入，以及在可用时更换服务商或模型的选项。
- 积分异常必须区分余额不足、预留失败和支付失败。
- 最终合成失败时保留全部已批准镜头，并允许只重试合成。
- 全局服务异常需要说明当前任务是否安全，以及是否会自动恢复。

## 14. MVP 页面范围

- 官网首页。
- Explore 案例页。
- 积分包页面。
- 注册、登录和账户恢复。
- 创作者首页与项目列表。
- 系列详情、角色库和风格库。
- 新建剧集向导。
- Episode Studio 单集工作台。
- 生成进度与审阅状态页面。
- 导出流程与导出记录。
- 积分购买结账、余额和消费明细。
- 账户、隐私、删除和支持本地化的偏好设置。

## 15. 无障碍与响应式

- 核心流程满足 WCAG 2.2 AA 对比度和键盘操作要求。
- 焦点、选中、进度、警告和失败状态不能只依赖颜色表达。
- 官网和账户相关页面完整支持响应式布局。
- 完整 Episode Studio 主要面向桌面和大尺寸平板。
- 小屏设备支持进度查看、内容审阅、评论和简单确认；MVP 不要求在手机上进行密集时间线编辑。

## 16. 测试与验收标准

### 16.1 验收标准

- 新用户可以提供英文脚本和角色设定，并创建一集 5–10 分钟漫剧。
- 用户可以在视频生成前检查和修改场景规划与成本预估。
- 单个镜头失败或重生成不会导致整集重新生成。
- 刷新、关闭浏览器或换设备登录后，可以恢复生成进度。
- 平台失败不会造成错误的永久积分扣除。
- 完成的剧集可以预览，并导出 16:9 或 9:16 成片。
- 官网、注册、积分购买、创作和导出构成完整可用闭环。

### 16.2 测试覆盖

- 单元测试：脚本解析边界、状态转换、成本展示和积分计算。
- 集成测试：任务编排、重试、回调幂等、积分预留、结算和失败补偿。
- 组件测试：向导校验、任务状态、警告和镜头检查器。
- 端到端测试：从注册到导出，外部模型使用可控测试替身。
- 无障碍检查：键盘流程、焦点可见性、标签和对比度。
- 响应式检查：公开页面，以及工作台支持的小屏监控和审阅流程。

## 17. MVP 明确不包含

- 订阅套餐。
- 多人实时协作编辑。
- 模板、角色或剧集交易市场。
- 原生移动应用。
- 手机端完整时间线编辑。
- 自研或训练基础模型。
- 自动发布到社交平台。
- 团队角色、审批和企业管理功能。

以上排除项用于确保首版聚焦个人创作者从脚本到导出的完整工作流。

## 18. 技术架构概览

MVP 采用 **Web + API + Worker** 三服务结构，代码组织为模块化单体。三个应用独立部署和扩缩容，通过共享包保持类型、领域规则和可观测性一致。

```text
apps/
  web/             Next.js
  api/             Hono + Node.js
  worker/          BullMQ consumers + FFmpeg

packages/
  auth/            Better Auth 配置与服务端鉴权能力
  domain/          领域实体、状态机和业务规则
  contracts/       Zod 请求、响应和任务载荷契约
  db/              Drizzle Schema、查询和迁移
  providers/       模型供应商适配器
  observability/   日志、指标和追踪
```

技术栈：

- Web：Next.js + TypeScript。
- API：Hono + `@hono/node-server`。
- Worker：Node.js + TypeScript + BullMQ。
- 数据库：PostgreSQL + Drizzle ORM。
- 鉴权：Better Auth。
- 队列：Redis + BullMQ。
- 媒体处理：FFmpeg 和 FFprobe。
- 文件：S3 兼容对象存储 + CDN。
- 契约校验：Zod。
- 可观测性：OpenTelemetry、结构化日志、指标和错误追踪。

### 18.1 Web 边界

- 负责官网、创作者首页、向导、Episode Studio、积分与账户界面。
- 部署到 Vercel。
- 不直接访问 PostgreSQL、Redis、对象存储密钥或模型供应商。
- 只通过版本化 API 和短时效签名 URL 操作业务数据与文件。
- 通过 Vercel Rewrite 将 `/api/*` 同源代理到 Hono API。

### 18.2 API 边界

- 负责鉴权、Workspace 权限、系列、剧集、场景、镜头、积分、支付、生成命令、签名上传和进度流。
- 部署到常驻 Node.js 容器，不使用 Edge Runtime。
- API 前缀为 `/api/v1/*`，Better Auth 路由为 `/api/auth/*`。
- 负责所有业务写操作、事务和 Outbox 事件。
- 提供 OpenAPI 文档与类型安全客户端契约。
- 通过 Server-Sent Events 推送任务进度，客户端断线后携带事件游标重连，并以轮询作为兜底。

### 18.3 Worker 边界

- AI Worker 负责脚本分析、场景规划、模型调用、回调处理和任务编排。
- Media Worker 负责媒体检查、转码、字幕、音轨和 FFmpeg 最终合成。
- AI Worker 与 Media Worker 使用不同队列和资源配置，独立扩缩容。
- Worker 可以访问受限的数据库、队列、对象存储和模型密钥，但不接收或转发用户 Session Cookie。
- Worker 不依赖 Web 页面、Next.js 路由或 Hono 路由代码。

## 19. Better Auth 鉴权设计

Better Auth 实例由 Hono API 持有，并挂载到 `/api/auth/*`。

- Hono 鉴权中间件通过请求 Headers 获取 Session，并将 `user` 和 `session` 写入请求上下文。
- Better Auth 表与业务表位于同一 PostgreSQL 实例，但分别管理 Schema 和迁移边界。
- Better Auth User 与业务 Workspace 分离。
- 用户首次注册成功后，通过幂等流程创建默认 Workspace 与积分账户。
- Web 使用 Better Auth Client，不自行签发或验证 Session。
- 生产环境通过同源代理访问鉴权 API，避免第三方 Cookie 和 Safari ITP 问题。
- `trustedOrigins` 使用明确白名单，生产配置中不得包含 localhost。
- Session Cookie 必须启用 Secure、HttpOnly 和合适的 SameSite 策略，并保持尽可能小的作用域。
- 如保存 OAuth Token，必须启用应用层加密；OAuth 密钥仅保存在 API 的 Secret Manager。
- Worker 使用内部服务身份和短期签名任务令牌，不使用用户 Cookie。

## 20. PostgreSQL 核心数据模型

### 20.1 身份与归属

- `user`：由 Better Auth 管理的用户身份。
- `workspace`：所有业务资源的归属边界；MVP 一个用户拥有一个默认 Workspace。
- `workspace_member`：预留未来团队能力，MVP 只创建 Owner。

### 20.2 系列与角色

- `series`：系列名称、风格手册和默认生成设置。
- `character`：系列内稳定的角色身份。
- `character_version`：角色外观描述、提示词、参考素材和声音配置版本。

### 20.3 剧集与镜头

- `episode`：脚本版本、生成设置、当前状态和预计时长。
- `scene`：场景顺序、摘要、预计与实际时长。
- `shot`：镜头顺序、台词、动作和时长。
- `shot_version`：提示词、模型档位、生成参数、候选状态与批准状态。

Scene 和 Shot 使用可排序 Rank，调整顺序时不需要重写所有同级记录。

### 20.4 生成与文件

- `generation_run`：一次用户生成操作，记录操作类型、预估成本、状态与发起人。
- `generation_task`：可独立执行与重试的任务，记录供应商任务 ID、尝试次数、进度和错误。
- `asset`：不可变文件记录，保存对象存储 Key、校验和、MIME、尺寸、时长和状态。
- `export`：最终导出的格式、画幅、合成任务与资产。

供应商任务 ID 只能作为外部引用，不得充当领域对象 ID。业务公开 ID 使用不可预测的 UUID。

### 20.5 积分

- `credit_account`：Workspace 的可用积分和预留积分。
- `credit_ledger_entry`：购买、预留、结算、释放、退款和人工补偿记录。

积分账本只允许追加。历史记录不得更新或删除，纠错通过补偿记录完成。每条账本记录关联 Workspace、Generation Run、Generation Task 和幂等键。

### 20.6 并发控制

- 可编辑记录使用 Revision 字段进行乐观锁。
- 状态迁移使用条件更新，确保旧状态符合预期。
- 积分预留和结算时锁定 Credit Account 记录。
- 任务完成、资产关联与积分结算在同一个 PostgreSQL 事务中提交。

## 21. API 与契约设计

- 所有业务端点使用 `/api/v1` 前缀。
- 输入、输出和错误结构由共享 Zod Schema 定义。
- 写操作支持客户端提供的 `Idempotency-Key`。
- 错误响应包含稳定错误码、可本地化消息 Key、Trace ID 和可恢复动作，不直接暴露内部异常。
- 列表接口使用 Cursor 分页。
- 更新接口携带 Revision；版本冲突返回明确的冲突响应。
- 上传接口先校验 Workspace、用途、文件类型、大小和配额，再签发短时效上传 URL。
- SSE 事件包含递增游标、Generation Run ID、Task ID、状态、进度和安全的摘要信息。
- API 契约生成 OpenAPI 文档；鉴权接口文档与业务接口文档可分别展示。

## 22. Outbox 与任务投递

创建生成任务时，API 在一个数据库事务中完成：

1. 校验权限、输入与积分。
2. 创建 Generation Run 和初始 Generation Task。
3. 预留积分。
4. 写入 Outbox Event。

Outbox Dispatcher 将未发布事件投递到 BullMQ，并在数据库记录发布结果。这样可避免“业务数据已保存但任务未入队”的不一致。

PostgreSQL 是任务与业务状态的唯一可信来源。Redis 和 SSE 仅作为任务、进度与事件的传递机制。Redis 数据丢失后，系统可根据 Outbox 和 Generation Task 重建未完成任务。

## 23. 剧集生成编排

整集生成使用持久化任务图：

**解析脚本 → 规划场景 → 创建镜头 → 并行生成视频与配音 → 最终合成**

- 一个用户操作创建一个 Generation Run。
- Generation Run 内含多个 Generation Task。
- 任务幂等键由 `run + operation + target + version` 构成。
- 每个任务载荷包含明确版本号，避免新旧 Worker 混用不兼容载荷。
- 镜头任务可以在供应商和账户限额范围内并行。
- 最终合成只读取用户已批准的 Shot Version。
- 单个镜头失败不阻断其他镜头。
- 取消操作停止尚未开始的任务，并尽力取消供应商任务；已完成的可计费工作正常结算。

### 23.1 重试策略

- 网络错误、HTTP 429 和供应商 5xx：带随机抖动的指数退避，并遵守供应商重试上限。
- 无效输入与内容审核拒绝：不自动重试。
- 任务超时：先查询供应商任务状态，再决定是否重新提交。
- 每次尝试记录开始、结束、错误类别、供应商和外部任务 ID。
- 超过最大尝试次数后进入 Failed 或 Needs Review。

### 23.2 回调策略

- 验证供应商或支付服务的回调签名。
- 以 `provider + event_id` 去重，并保存原始事件摘要或哈希。
- 回调入口快速确认接收，实际业务处理通过内部任务异步执行。
- 回调乱序时按供应商任务状态机和事件时间进行条件更新。
- Reconciler 定期查询长时间无回调的外部任务。

## 24. 模型供应商适配层

用户不直接选择供应商，只选择产品化质量档位：

- Draft：快速预览、较低分辨率和较低成本。
- Standard：质量、速度和成本平衡。
- Pro：使用当前可用的高质量方案。

每类模型能力通过统一适配器接口提供：

- 提交任务。
- 查询状态。
- 取消任务。
- 规范化进度。
- 规范化错误。
- 验证回调。
- 获取或接收生成结果。
- 返回实际计费单位。

Provider Router 根据能力匹配、服务健康、区域、审核结果、价格上限和降级配置选择供应商。用户确认价格后，不得在未重新确认的情况下切换到更高成本路径。

适配层隔离供应商字段、状态和错误码。供应商 Schema 不得泄漏到领域实体、公共 API 或前端组件。

## 25. 积分预留与结算

积分生命周期为：

**Estimate → Reserve → Execute → Settle**

- Estimate 根据档位、镜头时长、分辨率和操作类型生成估算。
- Reserve 在数据库事务中从可用积分转为预留积分。
- Execute 开始后，任务记录实际完成的可计费单位。
- Settle 扣除实际费用，并释放剩余预留。
- 供应商或平台失败时，释放未使用预留。
- 用户取消时，只结算已完成的可计费单位。
- 如果最终费用可能超过已确认上限，任务暂停并请求用户再次确认。

账本不变量：

- 可用积分和预留积分不得为负。
- 同一任务不得重复预留或重复结算。
- Account 汇总值必须与 Ledger 聚合结果一致。
- 任务状态更新与积分结算必须处于同一个数据库事务。
- 定时 Reconciler 检查长期未结算预留和账本差异。

## 26. 文件与媒体处理

- 浏览器只通过短时效签名 URL 直接上传对象存储。
- API 签发地址前校验 Workspace、用途、声明类型、大小和配额。
- 上传完成后，Media Worker 检查真实 MIME、媒体参数、校验和与安全状态。
- 原始素材、生成中间产物和最终导出使用独立路径与生命周期规则。
- Asset 记录不可变；替换文件时创建新 Asset。
- 私有素材使用短时效签名下载地址，不暴露永久公开 URL。
- 最终合成使用 FFmpeg；FFprobe 在任务开始和完成后验证输入与输出。
- 对象上传成功但数据库写入失败时，Reconciler 按校验和接管文件或按保留策略清理孤立对象。

## 27. 部署拓扑

- Web 部署到 Vercel。
- Hono API 部署到常驻 Node.js 容器。
- AI Worker 和 Media Worker 分别部署到容器平台并独立扩缩容。
- PostgreSQL、Redis 和 S3 兼容对象存储使用托管服务。
- 首发阶段使用单一北美主区域，API、PostgreSQL、Redis 与 Worker 位于同一区域。
- CDN 为签名私有素材和公开成片提供全球分发。
- 开发、预发布和生产使用完全隔离的数据库、队列、存储桶和密钥。
- 数据库迁移由独立发布任务执行，不在应用启动时自动执行。

具体云供应商在实施计划中根据价格、区域、BullMQ 兼容性、备份能力和容器资源限制确定。领域接口与存储接口不得绑定具体厂商。

## 28. 安全设计

- 所有业务写操作校验 Session、Workspace 所有权、Revision 和幂等键。
- API、AI Worker 和 Media Worker 使用最小权限的独立服务身份。
- 数据库、Redis、对象存储和模型密钥存放于部署平台 Secret Manager。
- 敏感密钥不得写入数据库、客户端包、任务载荷或日志。
- 支付与模型回调必须验签。
- 下载和上传签名 URL 使用短有效期，并限制操作和对象路径。
- 日志默认隐藏脚本全文、提示词、Cookie、Token、OAuth 凭据和签名 URL。
- 内容审核结果与用户输入分开存储，并限制访问范围。
- 数据删除任务覆盖数据库引用、对象存储资产和适用的供应商产物。

## 29. 可观测性与运维

Web、API 和 Worker 共享以下关联标识：

- Trace ID。
- User Action ID。
- Generation Run ID。
- Generation Task ID。

OpenTelemetry 串联 API、Outbox、队列、Worker、供应商调用和对象存储操作。

核心指标：

- 队列长度和最老任务等待时间。
- 各质量档位的生成耗时与成功率。
- 各供应商成功率、超时率和重试率。
- 单位成片分钟的实际模型与媒体成本。
- 积分预留、结算差异和长期未结算数量。
- 最终合成失败率。
- 孤立对象和缺失对象数量。

重点告警：

- 任务持续排队。
- 回调积压或长时间未到达。
- 积分无法结算或账本不一致。
- 数据库连接池耗尽。
- Redis 不可用。
- 最终合成失败率异常上升。

## 30. 备份与灾难恢复

- PostgreSQL 开启自动备份和时间点恢复。
- 定期执行数据库恢复演练。
- Asset 保存校验和与存储位置，并定期抽样检查文件完整性。
- Redis 和队列不作为唯一数据来源。
- 定期演练从 PostgreSQL Outbox 和 Generation Task 重建队列。
- 为原始素材、中间产物、失败产物和最终导出分别定义保留周期。
- 将数据库恢复目标、任务恢复目标和文件恢复策略写入运维手册。

## 31. 技术测试与发布门槛

### 31.1 测试

- Domain 单元测试：状态机、镜头版本、费用计算和账本不变量。
- API 集成测试：Better Auth、Workspace 隔离、乐观锁、幂等接口、签名上传和 Outbox。
- Worker 测试：重试、超时、取消、回调乱序、重复回调和积分补偿。
- Provider 契约测试：所有适配器必须通过统一测试套件。
- E2E：注册、购买积分、创建系列、生成单集、局部重做和导出。
- 故障注入：Redis 暂时不可用、供应商超时、数据库提交失败，以及文件上传成功但数据库回写失败。
- CI 使用可控模型供应商替身，不依赖真实付费生成。

### 31.2 发布

- 数据库迁移必须向后兼容当前线上 API 和 Worker。
- 破坏性迁移采用 Expand → Migrate → Contract 三阶段。
- Worker 任务载荷必须包含 Schema Version。
- 新版本先部署兼容旧任务载荷的 Worker，再逐步投递新版本任务。
- 发布前验证 Better Auth 回调地址、可信来源、支付回调和模型回调配置。
- 发布后执行注册、生成测试任务、积分结算和导出冒烟测试。

## 32. 产品难点与风险控制

本产品的核心挑战不是生成单个视频镜头，而是以用户可接受的成本，稳定生成一集 5–10 分钟、角色一致、剧情连贯且支持局部修改的漫剧成片。

### 32.1 P0：长视频角色与风格一致性

**风险：**角色脸型、发型、服装、画风、场景和道具可能在不同镜头间漂移。单个镜头效果良好，不代表整集具备可连载的一致性。

**控制措施：**

- 系列保存角色和风格版本，剧集与镜头引用明确版本。
- 为角色维护结构化外观描述、正反面参考图、服装和声音配置。
- 镜头生成时固定角色与风格输入，不只依赖自然语言提示词。
- 在高清生成前生成低成本分镜预览或 Animatic。
- 对角色、画风和关键道具执行自动一致性检查，并将结果作为可操作警告展示。
- 用户可以逐镜头重生成，不必重新生成整集。

**验证门槛：**使用固定角色、固定场景和 20–30 个连续镜头进行压力测试。达到团队事先定义的一致性通过率后，才能扩大单集时长。

### 32.2 P0：单位经济模型与成本失控

**风险：**一集可能包含几十个镜头。视频生成、失败重试、高清重做、存储、带宽和最终合成会快速放大成本。供应商涨价或异常重试可能直接侵蚀毛利。

**控制措施：**

- 持续记录每个任务、镜头、成片分钟和质量档位的实际成本。
- 积分定价包含供应商波动、失败重试和基础设施成本的安全缓冲。
- 生成前展示成本区间，并设置用户确认的最高消费上限。
- 限制自动重试次数和单次生成并发。
- 先生成低成本 Animatic，用户批准后再执行高成本视频任务。
- Provider Router 不得在未经确认的情况下切换到更高成本路径。

**验证门槛：**在真实模型调用数据基础上确认 Draft、Standard 和 Pro 三档的单位成片分钟成本、P50/P95 重试成本及毛利区间。未建立可靠成本模型前，不开放无限长度或无限重试。

### 32.3 P0：整集叙事与成片质量

**风险：**单镜头质量并不能保证场景节奏、台词衔接、角色表演和整集叙事成立。一键生成可能产生技术上完整但不可发布的成片。

**控制措施：**

- 将脚本解析、场景规划、镜头表和 Animatic 作为独立可审阅阶段。
- 在昂贵视频生成前，要求用户确认镜头顺序、时长与主要台词。
- 自动模式使用受控的节奏、机位和运动模板。
- 高级模式允许拆分、合并、重排和局部重做镜头。
- 最终合成前集中展示异常镜头、音频缺失和节奏风险。

**验证门槛：**目标用户能够仅依靠分镜和 Animatic 发现并修正主要叙事问题，且不需要通过多次整集重生成来完成作品。

### 32.4 P0：异步生成链路可靠性

**风险：**多供应商异步任务可能出现超时、重复回调、乱序回调、部分成功、队列丢失和文件与数据库状态不一致。

**控制措施：**

- 使用持久化 Generation Run 和 Generation Task 记录任务真相。
- 所有生成任务、回调和积分操作使用稳定幂等键。
- API 使用数据库事务和 Outbox 提交任务。
- 回调验签并去重，实际业务处理异步执行。
- Reconciler 定期修复卡住任务、未结算积分和孤立对象。
- Redis 只负责传递，队列可以从 PostgreSQL 重建。

**验证门槛：**通过重复回调、回调乱序、Redis 重启、供应商超时、Worker 中断和数据库提交失败等故障注入测试。

### 32.5 P0：积分与实际计费不一致

**风险：**可能出现重复扣费、失败仍扣费、少扣导致亏损，或预留积分长期无法释放。

**控制措施：**

- 使用只追加的积分账本。
- 严格执行 Estimate、Reserve、Execute、Settle 生命周期。
- 任务状态更新与积分结算处于同一个数据库事务。
- 供应商失败释放未使用预留；用户取消只结算已完成工作。
- 定期校验账户汇总值与账本聚合值。
- 所有人工纠错使用补偿记录，不修改历史账目。

**验证门槛：**在并发提交、重复请求、回调重复、取消和失败补偿测试中，始终满足积分不变量。

### 32.6 P1：模型供应商依赖

**风险：**供应商的价格、限流、模型能力、内容政策、可用区域和 API 可能发生变化。

**控制措施：**

- 用户选择产品质量档位，不直接依赖供应商品牌。
- 所有供应商通过统一 Provider Adapter 接入。
- 标准化任务状态、进度、错误和计费单位。
- 保留主供应商和降级供应商配置。
- 持续监控供应商质量、成功率、耗时和单位成本。
- 供应商切换不得突破用户已确认的价格上限。

### 32.7 P1：角色资产版本管理

**风险：**创作者需要跨集复用角色，但更新角色定义可能破坏旧剧集的可复现性。

**控制措施：**

- Character 和 Character Version 分离。
- 每个剧集与镜头锁定具体角色版本。
- 剧集内修改默认只影响当前剧集。
- 将变更提升为系列默认值必须经过用户明确确认。
- 已完成导出保存当时采用的所有角色和生成版本引用。

### 32.8 P1：创作流程复杂度

**风险：**一键生成缺少控制，专业编辑器又可能使新用户在体验价值前流失。

**控制措施：**

- 保持五步快速向导与高级工作台双层结构。
- 新用户通过默认配置快速得到 Animatic。
- 高级设置按需展开，不在首屏展示所有模型参数。
- 每一步展示当前产物、下一步成本和可返回修改的范围。
- 保存阶段性结果，用户离开后可以继续。

### 32.9 P1：媒体合成资源压力

**风险：**5–10 分钟视频的下载、探测、转码和合成可能大量消耗 CPU、内存、临时磁盘和网络，并导致任务超时。

**控制措施：**

- Media Worker 与 AI Worker 独立部署和扩缩容。
- 根据输出时长和分辨率设置明确的 CPU、内存、磁盘与超时预算。
- 支持分段合成和最终拼接，失败时避免重做已完成分段。
- 开始合成前用 FFprobe 验证所有输入。
- 限制同一 Workspace 的高成本合成并发。
- 监控合成耗时、资源峰值、失败原因和单位分钟成本。

### 32.10 P1：版权、肖像权与内容合规

**风险：**用户可能上传未授权角色、受保护 IP、真人肖像或违规内容。不同市场和模型供应商的政策也可能不一致。

**控制措施：**

- 上传时要求用户确认拥有相应权利。
- 对输入、提示词和生成结果执行分阶段审核。
- 保存必要的审核类别、处理结果和审计记录。
- 提供投诉、下架和申诉流程。
- 项目默认私有，公开发布必须由用户主动操作。
- 服务条款明确用户责任、平台处理边界和禁止内容。

### 32.11 P2：首次体验与留存

**风险：**完整视频需要较长等待时间，用户可能在看到价值前离开。

**控制措施：**

- 提供示例系列、示例角色和可编辑脚本模板。
- 优先生成脚本解析、分镜和 Animatic，让用户尽快看到结果。
- 分阶段显示成果，不让用户只面对进度条。
- 支持页面关闭后继续运行，并通过站内或邮件通知任务结果。
- 记录首个价值时刻：首次生成分镜、首次批准镜头和首次成功导出。

### 32.12 P2：全球化运营复杂度

**风险：**全球化不仅包括翻译，还涉及支付、税务、数据保留、模型区域和内容政策差异。

**控制措施：**

- 首版运营范围聚焦北美和英文。
- 架构支持本地化，但不在 MVP 同时运营所有市场。
- 支付、邮件、时间、货币和文案使用可替换的区域配置。
- 进入新市场前单独评估当地支付、税务、隐私与内容要求。

## 33. MVP 风险收缩约束

为降低首版不确定性，MVP 增加以下产品约束：

- 首发只提供 1–3 种经过验证的视觉风格。
- 推荐单镜头时长为 3–8 秒；超出范围时明确提示质量和成本风险。
- 为单集角色数量、镜头数量和生成并发设置可配置上限。
- 首版只重点支持一种主要配音语言，其他语言在验证后扩展。
- 首版至少具备一家主视频供应商；第二家供应商只承担明确的降级能力。
- 不提供开放式专业剪辑时间线，只提供漫剧所需的镜头排序、时长、台词、配音和局部重做。
- 高成本高清视频生成前必须先产生可审阅的低成本分镜或 Animatic。
- 未建立可靠单位成本数据前，不开放无限时长、无限重试或无限并发。

## 34. 上线前核心验证

### 34.1 单位经济模型

使用真实供应商与基础设施数据，计算每个质量档位的：

- 每镜头和每成片分钟成本。
- P50、P95 生成耗时。
- 首次成功率和平均重试次数。
- 视频、配音、存储、带宽与合成成本。
- 积分售价、实际毛利和供应商价格波动安全空间。

### 34.2 阶段式创作接受度

验证目标用户是否愿意采用：

**脚本 → 分镜 → Animatic → 高质量镜头 → 成片**

如果用户只能通过反复生成完整成片来发现问题，MVP 的成本和等待时间将不可持续。

### 34.3 连载级角色一致性

使用固定角色和场景生成连续 20–30 个镜头，由目标创作者从角色身份、服装、画风、场景连续性和可发布性五个维度评分。

若一致性尚不能达到连载要求，产品必须强化参考图、受控风格、人工审阅和局部重生成，而不是扩大自动化范围。
