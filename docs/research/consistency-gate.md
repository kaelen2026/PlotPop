# F-00 角色一致性门禁

## 1. 文档地位

`docs/ai-comic-drama-saas-design.md` §32.1 要求「达到团队**事先定义**的一致性通过率后，才能
扩大单集时长」。本文件就是那个事先定义。

**本文件必须在 F-00 第一次生成之前冻结。** 实验跑完后不得下调门槛 —— 事后调整门槛等于没有
门禁，而这是唯一一条能否决产品方向的关卡。

一致性不是单镜头属性，是序列属性。30 镜里 28 镜单独看都合格、坏的 2 镜正好在同一段对话中
间，「93% 通过」读起来是成功，那一集实际发不出去。因此门禁是四条约束，不是一个数字。

## 2. 测试集

来自 `docs/implementation-plan.md` §5.2，F-00 启动前固定，之后不得更换：

- 1 个测试系列。
- 2–4 个固定角色，含正反面参考图、服装与声音配置。
- 3 个固定场景。
- 20–30 个连续镜头，覆盖近景、远景、对话、动作和多人镜头。
- 镜长落在 3–8 秒推荐区间内（§33）。

下文所有比例按 30 镜计算。

## 3. 评分表

### 3.1 判定维度（唯一决定 pass / fail）

**可发布性** —— 二元判断，问题固定为：

> 作为一部连载漫剧中的一个镜头，这个镜头可以按现状发布吗？

单镜头通过的条件是 **≥2/3 评分者回答「是」**。

用二元而非 5 分制，是为了让评分者之间的分歧可度量。用可发布性而非五维平均，是因为平均会
掩盖最要命的那类失败：画风完美但脸不对，平均分 3.8 看着还行。

### 3.2 诊断维度（1–5 分，只记录，不参与判定）

失败镜头必须填，用于决定补救方向：

| 维度 | 问的是 |
|---|---|
| 角色身份 | 脸型、发型、五官是否仍是同一个角色 |
| 服装 | 服装与配饰是否与该角色版本一致 |
| 画风 | 线条、上色、渲染是否与风格手册一致 |
| 场景连续性 | 背景、道具、光线与机位关系放在前后镜头之间是否成立 |
| 动作可用性 | 运动是否自然可用，有无明显崩坏 |

诊断维度不设门槛。它们的作用是回答「为什么不通过」，从而决定去加强参考图还是收紧风格。

> `docs/ai-comic-drama-saas-design.md` §34.3 列五维，`docs/implementation-plan.md` §5.2 列
> 六维（多「动作可用性」）。此处采用六维口径：可发布性判定 + 上表五项诊断。

## 4. 四条门禁

四条全部满足才算 F-00 通过。

### Gate A｜单镜头首次通过率 ≥ 75%

30 镜中 **≥ 23 镜**首次生成即通过。

这一条管的是成本和用户手动负担，不是质量下限。逐镜头重生成是设计好的功能（§8、§32.1），
所以中等的首次通过率是架构预期而非失败。按每集 80 镜（5–10 分钟 ÷ 3–8 秒的典型值）推算，
75% 意味着用户每集手动重做约 20 个镜头，COGS 乘数 1.33×。

产品定位随之确定为**半自动专业工具**：向导给出可用初稿，Episode Studio 里逐镜头收尾。不是
一键成片。官网与积分页文案不得承诺后者。

### Gate B｜3 次重生成后仍不可用的镜头 = 0

硬门禁。每个首次失败的镜头最多重生成 3 次，30 镜必须全部在此预算内达到可发布。

一个修不好的镜头就可能卡住整集 —— 用户要么放弃这一集，要么改脚本绕开它。首次通过率可以
中等，收敛失败率必须为零。

### Gate C｜失败不得扎堆

- 不存在 3 个及以上**连续**镜头首次失败。
- 单个场景内首次失败的镜头不超过该场景镜头数的一半。

不要求「零相邻失败」：7–8 个失败随机散布在 30 个位置上，出现相邻对属于概率必然，那样的门槛
会因为运气而失败。3 连失败才是真扎堆的信号，且它直接对应 §32.3 的叙事风险 —— 连续坏镜头会
打断一段对话交换。

### Gate D｜序列级可发布

评分者按顺序观看**完成局部重做后**的完整 20–30 镜序列，回答：

> 连起来看，作为一集里的一个片段，你愿意发布这段吗？

**≥2/3 评分者回答「是」**。

判定对象是修完的版本，因为产品实际交付的就是修完的版本。但若为通过 D 所需的重做次数超出
Gate A 或 Gate B 的预算，记为 A 或 B 失败，不得记为 D 通过。

D 推不出来，必须直接问。前三条都是可计算的比例，只有这一条回答「这东西能不能拿出去」。

## 5. 评分规程

- **3 名目标创作者**，非团队成员。
- **盲评**：不告知质量档位、供应商、哪些镜头是重生成的第几次。Gate D 的「愿意发布」在评分者
  知道这是 AI 生成、知道该盯哪里的情况下没有意义。
- 评分者独立打分，不互相讨论后再提交。
- **口径校验**：三名评分者对单镜头 pass / fail 的两两分歧率 > 20% 时，视为评分表口径失效。
  必须先修订评分表定义并重新评分，**不得直接采用多数票结果** —— 分歧过大说明「可发布」这
  个词在三个人脑子里不是同一件事，此时任何通过率数字都不可信。

## 6. 经济复核

Gate A 的 75% 是从产品定位推出的，不是从成本推出的 —— F-00 跑完才有真实成本。

`1/p` 是 COGS 的直接乘数。p = 75% → 1.33×。拿到 `docs/research/unit-economics.md` 的实测
单镜头成本后必须复核：

```text
单镜头成本 × (1 / 0.75) × 每集镜头数  ≤  目标积分定价 - 目标毛利
```

不成立时，问题在成本而不在门槛。此时的动作是压成本或调整档位定义，**不是下调 Gate A** ——
下调 A 只会把成本压力转移成用户的手动重做时间。

## 7. 未通过时做什么

§34.3 已定方向：强化参考图、受控风格、人工审阅和局部重生成，**而不是扩大自动化范围**。
按失败的门禁分支：

| 失败的门禁 | 动作 |
|---|---|
| A | 补强角色参考图（正反面、服装、表情），收紧风格约束，减少首发可选风格数量 |
| B | 把该类镜头（多人、大动作、特定景别）列入不支持清单，或强制拆分为更简单的镜头 |
| C | 检查失败是否集中在某个角色或场景 —— 扎堆通常是系统性问题，不是随机波动 |
| D 未过而 A/B/C 通过 | 问题在叙事与节奏，不在一致性。转 §32.3 的控制措施，不要继续调一致性 |

任何情况下都不得以「先上线再优化」跳过本门禁。§33 已约定：未建立可靠数据前不开放无限时长、
无限重试或无限并发。

## 8. 重审触发条件

冻结后，仅在以下情况重跑并重新定义门禁：

- 更换主视频供应商或主模型。
- 引入新的视觉风格（首发限 1–3 种）。
- 推荐镜长区间脱离 3–8 秒。
- 单集目标时长脱离 5–10 分钟。

上述之外，门禁一经冻结不再改动。
