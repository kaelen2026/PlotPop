# F-00 供应商评估记录

## 1. 文档地位

`docs/implementation-plan.md` §5.3 要求 F-00 产出供应商评估报告。本文件是那份报告的**结构**。

它与 `docs/research/consistency-gate.md` 的关系必须分清：

- `consistency-gate.md` 在第一次生成**之前**冻结，之后不得改动。
- 本文件在第一次生成**之后**填写。里面每一个空位都只能由实测数据填入。

本文件当前**没有任何实测数字**。所有标注 `<!-- 待实测填入 -->` 的位置在真实运行前必须保持为空。
写一个"大概是这样"的数字进去，读者无法把它和实测值区分开，而 F-07 的定价会建立在它上面。

## 2. 实验装置

一次性实验代码在 `scripts/research/`，包名 `@plotpop/research-harness`。

它**不在** `packages/providers`。那里是 F-07 的正式适配层（ADR-005 的八方法接口、Provider Router、
回调验签），本实验只需要 submit / poll / download 三步，把它写进正式包会留下一份需要长期同步的
第二实现。`apps/` 与 `packages/` 中任何代码都不得依赖本实验包。

它仍然是一个 workspace，原因只有一个：`.claude/rules/tdd.md` §2 要求长期挡回归的测试落在 runner
能跑到的位置，`pnpm test` 才会在 CI 里跑到它的单元测试。

## 4. 怎么跑

### 4.1 环境变量

实验脚本**自己解析自己的环境变量**，不接 `packages/config`。理由：`packages/config` 是三个服务的
启动契约（ADR-001），一次性实验凭据不该出现在 api 与 worker 缺它就起不来的 Schema 里。

凭据写在 `scripts/research/.env.research`（已被 `.gitignore` 忽略，不要写进仓库根 `.env`）。

| 变量 | 必填 | 说明 |
|---|---|---|
| `PLOTPOP_RESEARCH_PROVIDER` | 否 | `offline`（默认）或 `replicate` |
| `PLOTPOP_RESEARCH_API_TOKEN` | 真实供应商必填 | 供应商 API Token |
| `PLOTPOP_RESEARCH_MODEL` | 真实供应商必填 | `owner/name` 或版本号 |
| `PLOTPOP_RESEARCH_MODEL_INPUT` | 否 | JSON，模型专属 `input` 字段（`aspect_ratio` 之类） |
| `PLOTPOP_RESEARCH_UNIT_PRICE_USD` | 真实供应商必填 | 每计费单位价格，**从供应商价目表手抄**，脚本绝不猜 |
| `PLOTPOP_RESEARCH_BILLABLE_UNIT` | 否 | `output_second`（默认）/ `compute_second` / `request` / `generated_frame` |
| `PLOTPOP_RESEARCH_SPEND_CAP_USD` | 真实供应商必填 | 整轮硬上限，超过即停 |
| `PLOTPOP_RESEARCH_TIER` | 否 | `draft` / `standard`（默认）/ `pro` |
| `PLOTPOP_RESEARCH_RUN_ID` | 否 | 默认 `<日期>-<供应商>-<档位>`；断点续跑要复用同一个 |
| `PLOTPOP_RESEARCH_MAX_ATTEMPTS` | 否 | 默认 4 = 首次 + Gate B 允许的 3 次重生成，上限也是 4 |
| `PLOTPOP_RESEARCH_ATTEMPT_TIMEOUT_MS` | 否 | 单次尝试超时，默认 900000 |
| `PLOTPOP_RESEARCH_POLL_INTERVAL_MS` | 否 | 轮询间隔，默认 5000 |
| `PLOTPOP_RESEARCH_RUN_DIR` | 否 | 默认 `runs`（已忽略） |
| `PLOTPOP_RESEARCH_ASSET_DIR` | 否 | 默认 `assets` |
| `PLOTPOP_RESEARCH_FFPROBE` | 否 | ffprobe 路径，默认走 `PATH` |

缺任何一项必填变量时脚本一次性列出全部缺失项并退出。四项必填里两项是成本护栏：没有单价就算不出
成本，没有上限就等于无人值守地敞开花钱（§32.2）。

### 4.2 命令

```bash
# 零成本走通全链路，不需要凭据、不需要 ffmpeg
pnpm research generate
pnpm research report

# 真实供应商：先买一个镜头验证字段映射
pnpm research generate --only shot-01
pnpm research report          # 读一眼 usage、tierDrift、media 是否合理

# 确认无误后跑完整 30 镜（可随时中断，重跑自动续跑）
pnpm research generate

# 组织盲评
pnpm research review build    # 生成编码样本 + 空白评分表
pnpm research review score    # 填完后判定四条门禁
```

`--only` 不是方便功能，是成本控制：模型专属 `input` 字段名写错一次，用一个镜头发现要付一个镜头
的钱，用三十个镜头发现要付三十个。

真实运行需要本机装 ffmpeg（`ffprobe` 随它一起）。离线运行不需要。

### 4.3 花多少钱

脚本不猜价格，所以这里只能给量：

| 量 | 值 |
|---|---|
| 测试集镜头数 | 30 |
| 测试集总时长 | 141 秒（镜长 3–8 秒） |
| 最好情况：全部首次通过 | 30 次尝试 / 141 输出秒 |
| 预期情况：首次通过率 75% | 约 38 次尝试 / 约 180 输出秒 |
| 最坏情况：每镜用满 4 次 | 120 次尝试 / 最多 960 输出秒 |

按 `output_second` 计费时，`成本 ≈ 输出秒数 × 单价`。**建议把 `PLOTPOP_RESEARCH_SPEND_CAP_USD`
设成最坏情况的值**（`单价 × 8 × 120`），而不是预期值 —— 上限是为了防失控，设成预期值只会让一次
正常的重试把运行截断在中途。

失败的尝试也可能计费，脚本按此假设记账。

## 9. 附录：门禁定义中仍需在首次生成前敲定的判定细节

以下几处在 `consistency-gate.md` 里没有可执行到底的定义。**它们不改变任何门槛高低**，只是把口径
补齐；`scripts/research/src/review/gates.ts` 目前按右列实现，跑第一轮之前应确认或改正，之后
连同门禁一起冻结。

| 缺口 | 现有代码采取的口径 | 为什么必须先定 |
|---|---|---|
| Gate A 的分母是"30"还是"75%" | 按 `ceil(0.75 × 测试集镜头数)`；测试集固定 30 镜，故等于 23 | §2 允许 20–30 镜，§4 直接写 30 镜与 23 镜。两者只在 30 镜时一致 |
| 场景镜头数为奇数时"不超过一半" | `失败数 > 镜头数 / 2` 才算失败，即 9 镜场景允许 4 镜失败 | 本测试集第三场景是 9 镜，边界会被真实触发 |
| 首次即被内容审核拒绝的镜头 | 计入 Gate B 未收敛（无可发布版本） | 供应商拒绝生成的镜头永远到不了可发布，等于 Gate B 直接失败。若意图是"列入不支持清单"，需要在门禁里说明 |
| Gate D 用哪一个通过版本 | 每镜取**最早**通过的版本 | 取最好的一版会抬高 D，也会与成本口径（同样取最早）不一致 |
| 20% 分歧率的分母 | 两名评分者都打过分的全部样本，含重生成版本 | 只算首次尝试会让分歧率随重试数漂移 |
| 评分者不足 3 人 | 判为 `invalid_scorecard`，不出门禁结论 | §5 要求 3 人；少于 3 人时"≥2/3"的含义会变 |
| 评分者需要给哪些样本打分 | 全部交付出文件的尝试，首次与重生成一律编码后混在一起 | 这是 Gate A 能被无偏测量的前提；只评首次尝试等于告诉评分者哪些是首次 |
