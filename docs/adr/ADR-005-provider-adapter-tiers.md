# ADR-005 供应商适配器与产品质量档位

- 选了什么：用户只选 Draft / Standard / Pro 三个产品化档位，不选供应商。所有供应商通过统一 Adapter 接口接入（submit、getStatus、cancel、verifyCallback、normalizeProgress、normalizeError、fetchResult、getBillableUsage）。Provider Router 按能力、健康、区域、审核结果和价格上限选路。

- 否掉了什么 / 为什么：
  - **让用户直接选供应商或模型**。把供应商涨价、限流、区域限制、内容政策差异全部暴露给用户，换供应商就成了破坏性产品变更；用户也无从判断哪个模型适合自己的镜头。
  - **只对接一家并直接调用其 SDK**。供应商故障或涨价直接等于业务停摆，且供应商字段会渗进领域实体和前端组件，之后再抽象的成本远高于现在。
  - **接入现成的多模型网关做中间层**。通用网关倾向于抹平异步回调语义、计费单位和取消行为，而这三件恰是本产品必须精确掌握的——积分结算和失败释放都建立在它们之上。

- 当时的前提：视频生成供应商的价格、能力、政策变化快；首发至少一家主供应商，第二家只承担明确的降级能力；用户确认过的价格上限不得被自动路由突破。

- 已知代价：每家供应商都要通过同一套契约测试；档位与真实成本的映射需要靠 F-00 的实测数据持续维护；Router 的路由决策要落库以便追溯。

- 何时重审：某个档位只剩单一可用供应商且无降级路径；或供应商能力差异大到无法用同一接口表达（例如需要流式或交互式生成）。
