# ADR-002 PostgreSQL 作为业务与任务状态唯一可信来源

- 选了什么：PostgreSQL 持有全部业务与任务状态；Redis 和 SSE 只承担传递。Redis 数据丢失后，可依据 Outbox 与 Generation Task 重建未完成任务。

- 否掉了什么 / 为什么：
  - **让 BullMQ / Redis 持有任务状态权威**。Redis 丢数据即丢任务真相，无法回答"这个 run 现在到哪了"。更关键的是积分结算必须与任务状态更新在同一事务内提交，跨 Redis 与 PostgreSQL 做不到。
  - **以供应商任务状态为权威**。回调会乱序、重复、迟到甚至不到，供应商任务 ID 只能作为外部引用，不能充当领域对象 ID。
  - **事件溯源或另设独立状态存储**。MVP 规模用不上，反而多一处一致性边界要维护。

- 当时的前提：积分结算与任务状态必须同事务；用户关页面、刷新、换设备后任务要继续；单区域单 PostgreSQL 实例；Redis 是托管服务，可用性不是 100%。

- 已知代价：任务表承担高频状态写入，索引与 Reconciler 扫描要留性能预算；队列重建逻辑要自己实现并定期演练。

- 何时重审：任务状态写入成为 PostgreSQL 瓶颈（连接池耗尽或写放大）；或需要多区域部署使单实例不再可行。
