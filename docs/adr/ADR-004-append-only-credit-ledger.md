# ADR-004 只追加积分账本

- 选了什么：`credit_ledger_entry` 只允许追加，历史记录不更新不删除，纠错通过补偿记录完成。`credit_account` 汇总值与账本在同一事务内更新，由定时 Reconciler 校验二者一致。

- 否掉了什么 / 为什么：
  - **只存余额字段做加减**。无法回答"这 200 积分为什么被扣了"。退款争议、失败释放和人工补偿都需要逐笔溯源到剧集、场景、镜头、操作类型和任务编号。
  - **账本行可更新**（改状态而非追加新行）。并发下会丢更新，且审计链断裂——恰恰是重复扣费、失败仍扣费这类最需要复盘的场景失去证据。
  - **只存账本、余额每次实时聚合**。每次付费生成前都要全表聚合，而预留检查本身需要锁账户行，性能和实现复杂度都更差。

- 当时的前提：一次性积分包商业模式，无周期性额度重置；有真实支付与退款；生成失败必须释放未使用预留；`Estimate → Reserve → Execute → Settle` 是唯一积分生命周期。

- 已知代价：账本表持续单向增长，需要归档策略；余额与账本双写靠 Reconciler 兜底而非数据库天然保证。

- 何时重审：引入订阅制（周期性额度重置会改变账本语义）；或账本表规模开始影响余额与明细查询。
